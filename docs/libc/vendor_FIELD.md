# Vendored safeclib field compare/copy + collation (`vendor_FIELD`)

This change brings three **already-made** safeclib field/collation
implementations into the checked runtime. Nothing is reimplemented: the three
upstream translation units are `#include`d **verbatim**, with only
preprocessor symbol-prefix renames applied.

| --- | --- |

The integration block is exactly:

```c
#define strcmpfld_s cplus_v_strcmpfld_s
#define _strcmpfld_s_chk cplus_v__strcmpfld_s_chk
#define strcpyfld_s cplus_v_strcpyfld_s
#define _strcpyfld_s_chk cplus_v__strcpyfld_s_chk
#define strcoll_s cplus_v_strcoll_s
#define _strcoll_s_chk cplus_v__strcoll_s_chk

#include "extstr/strcmpfld_s.c"
#include "extstr/strcpyfld_s.c"
#include "extstr/strcoll_s.c"
```

The public names `strcmpfld_s`, `strcpyfld_s`, `strcoll_s` appear only inside
upstream `FOR_DOXYGEN` blocks, so they produce no object symbols; the symbols
actually present in the object are the three prefixed `_chk` entry points.
The upstream-internal `_strcmpfld_s_uchk` / `_strcoll_s_uchk` helpers remain
unprefixed, exactly as upstream emits them, and are not part of the declared
public surface.

### Additional prefix-only renames (linkage, documented — nothing skipped)

Two upstream bodies call safeclib helpers that `scripts/build_safecrt.sh`
already exports under its own `cplus_sc_*` prefix in
`build/safe/libcplus_safecrt.a`:

```c
#define invoke_safe_str_constraint_handler \
    cplus_sc_invoke_safe_str_constraint_handler
#define _strnlen_s_chk cplus_sc__strnlen_s_chk
```

These are prefix-only renames of two call sites so the vendored object links
against the checked runtime's already-prefixed definitions. No helper is
reimplemented, no upstream source line is changed, and no build script was
edited. (`handle_str_bos_overflow` is already exported unprefixed by that
library; `__bzero` and `strcoll` come from the platform libc.)

### `strcoll_s` locale configuration

No special locale configuration was needed and **nothing was skipped**.
`strcoll_s.c` uses the standard C function `strcoll()` from `<string.h>`, which
resolves the `LC_COLLATE` category at run time; all three sources compiled
cleanly with the exact command below. The test runs in the default `"C"`
locale and asserts only sign relationships that hold there.

## Verification (exact commands and results)

All commands were run from the repository root on branch `agent/modern-stdlib`.
`build/safe/config.h` was already present (generated by
`sh scripts/build_safecrt.sh`); no compiler, runtime, or build-script file was
modified.

### 1. Compile the integration translation unit

```sh
/usr/bin/clang -O2 -std=c99 -D__STDC_WANT_LIB_EXT1__=0 \
  -Ithird_party/safeclib/include -Ibuild/safe -Ithird_party/safeclib/src \
  -Istdlib/safe -Wno-macro-redefined \
  -c libc/src/safecrt_vendor/field_group.c -o /tmp/field_group.o
```

Result: exit 0, no diagnostics.

### 2. Confirm exported symbols

```sh
nm -g /tmp/field_group.o | grep cplus_v | sort
```

```

0000000000000150 T _cplus_v__strcpyfld_s_chk
00000000000005d0 T _cplus_v__strcoll_s_chk
```

(Leading `_` is the Mach-O symbol convention; the C names are the three
prefixed `_chk` functions declared in `cplus_vendor_field.h`.)

### 3. Build and run the standalone test (timeout 30)

```sh
/usr/bin/clang -std=c99 -Wall -Wextra -pedantic \
  -Ilibc/install-include tests/libc/test_vendor_field.c \
  /tmp/field_group.o build/safe/libcplus_safecrt.a \
  build/libc/libcplus_hardened.a -o /tmp/test_vendor_field
timeout 30 /tmp/test_vendor_field
```

Result: link clean (no diagnostics), test exited 0, output:

```
vendor_field: 59 0
```

The `IGNORE CONSTRAINT HANDLER: (…)` lines are emitted by safeclib's default
ignore handler for the deliberate constraint-violation checks (NULL pointers,
zero/oversized/one-over bounds) and are expected. Note that
`EOVERFLOW` is the platform `<errno.h>` value (84 on this macOS host); the test
compares against `EOVERFLOW` rather than a hard-coded number.

### Coverage in `test_vendor_field.c`

- Field compare (`cplus_v__strcmpfld_s_chk`): equal/unequal results and sign,
  NUL-inside-field comparison, truncation at `dmax`, known-`BOS` success, NULL
  `dest`/`src`/`resultp`, zero `dmax`, `dmax > RSIZE_MAX_STR`, one-over bounds.
- Field copy (`cplus_v__strcpyfld_s_chk`): `slen` bytes copied with slack
  zeroed, embedded NUL copied, known-`BOS` success, `slen == 0` no-write
  (including NULL `dest` early return), NULL `dest`/`src`, zero `dmax`,
  `slen > dmax`, `slen > RSIZE_MAX_STR`, one-over bounds.
- Collation (`cplus_v__strcoll_s_chk`): equal/less/greater results, known-`BOS`
  success, NULL `dest`/`src`/`resultp`, zero `dmax`, `dmax > RSIZE_MAX_STR`,
  one-over bounds, and `resultp` cleared on every violation.

## ABI impact

Additive only. Three new prefixed symbols are added to the checked runtime;
no existing symbol is renamed, removed, or changed. The install header
`cplus_vendor_field.h` is self-contained (it spells out `size_t`/`int`, which
are the pinned `rsize_t`/`errno_t` underlying types) and C++-safe via
`extern "C"`.
