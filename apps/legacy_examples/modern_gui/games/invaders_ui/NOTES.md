# Headless Nuklear + SDL3 invaders HUD (`modern_gui/games/invaders_ui`)

## Explicit scope statement

`invaders_ui.cp` is a **deterministic teaching game**, not an interactive game
and not a safety proof.  There is no keyboard/event loop, no audio, no wall
clock, no network and no randomness beyond a fixed seed (`0x13579BDF`) that
only picks the initial ship column.  The formation is fixed, the bullet pool
is bounded, and every later state is a pure function of the fixed command
sequence.  Identical input yields a byte-identical transcript on the same
build/machine.  SDL3 runs on `SDL_VIDEODRIVER=dummy` with a hidden software-
rendered window; Nuklear draws a real HUD window with three fixed text lines
(`SCORE n`, `LIVES n`, `WAVE n`) and a snapshot is sampled at two fixed pixels.

The refusals below demonstrate that coded guards fire cleanly (exit 2, a
`REFUSED` line with stdlib error code/category, no crash and no timeout).
They are **behavioural demonstrations, not proof of absence of bugs** and not
evidence of live in-game success.  No live game, Wine or retail executable is
involved.

## Files

- `invaders_ui.cp` — the C+ program (uses `stdlib/window.hp`,
  `stdlib/graphics.hp`, `stdlib/gui.hp`, `stdlib/error.hp`).
- `run.sh` — builds, runs 9 scenarios under `timeout 30`, prints the summary.
- `NOTES.md` — this file.
- `bin/` — generated binary, logs and transcripts (regenerated by `run.sh`).

No files outside this directory were created or modified.

## Exact build command (from the repository root)

Nuklear is compiled once.  The repository's standard harness
(`tests/stdlib/run_stdlib_tests.sh`) already produced
`build/ext/libnuklear.a`; `run.sh` links that artifact and, if it is absent,
falls back to compiling `third_party/nuklear/nuklear_impl.c` once into a local
static library inside `bin/` (never writing outside this example's directory).

```sh
pkg-config --cflags --libs sdl3
# -I/opt/homebrew/include -L/opt/homebrew/lib -Wl,-rpath,/opt/homebrew/lib -lSDL3

./build/c+ build apps/legacy_examples/modern_gui/games/invaders_ui/invaders_ui.cp \
  --sanitize=none \
  $(pkg-config --cflags --libs sdl3) \
  -I. -Ithird_party/nuklear -Lbuild/ext -lnuklear \
  -o apps/legacy_examples/modern_gui/games/invaders_ui/bin/invaders_ui
```

Exit status 0.  The C backend emits five harmless `clang` warnings that the
linker-only operands (`-lSDL3`, `-lnuklear`, `-Wl,-rpath,...`, `-L...`) are
unused during the compile step; the same warnings appear in the repository's
stdlib test harness.  `--sanitize=none` is required in this environment: the
default sanitized build fails while compiling the shared instrumented runtime
because `c-plus-core/runtime/cplus_runtime.c` references
`CPLUS_EXIT_ARITHMETIC` / `CPLUS_EXIT_CONVERSION`, which are absent from this
repository's `runtime/include/cplus/cplus.h`.  That mismatch is outside this
example's file ownership; the unsanitized build is clean.

## Positive scenarios

`LLLLLLLLLFFFFFFFFFFFF` (except `default`, which uses the built-in
`LFRFLFSRFLFLSFRFLFFFF`).  They exit 0, write empty stderr and contain the
fixed HUD lines plus `PIXEL hud_nonbg=1` at every one of the 21 frames.

```sh
$ SDL_VIDEODRIVER=dummy timeout 30 bin/invaders_ui 'LLLLLLLLLFFFFFFFFFFFF'

$ SDL_VIDEODRIVER=dummy timeout 30 bin/invaders_ui L L L L L L L L L F F F F F F F F F F F F
```

## Safety-refusal evidence

Every adverse case exited exactly **2** (never 124/134/139), wrote empty
stdout and emitted one `REFUSED` line on stderr.  Codes are the wrapped stdlib
error's own `code()`/`category()`: 108/1 is `CPLUS_EXIT_UNSUPPORTED` /
`STDLIB_CATEGORY_INVALID`; 101/5 is `CPLUS_EXIT_BOUNDS` /
`STDLIB_CATEGORY_BOUNDS`.

| # | exact command | rc | stderr (verbatim) |
| --- | --- | --- | --- |
| 1 | `bin/invaders_ui X` | 2 | `REFUSED reason=bad-command code=108 category=1 message=command out of range (expected L/R/S/F)` |
| 2 | `bin/invaders_ui --bullets=64` | 2 | `REFUSED reason=pool-oversized code=101 category=5 message=bullet pool request out of range 1..16` |
| 3 | `bin/invaders_ui --null-surface` | 2 | `REFUSED reason=null-surface code=108 category=1 message=guarded_pixel: null surface` |
| 4 | `bin/invaders_ui --null-context` | 2 | `REFUSED reason=null-context code=108 category=1 message=guarded_hud: null context` |
| 5 | `bin/invaders_ui L L ... L  (129 tokens)` | 2 | `REFUSED reason=too-many-ticks code=101 category=5 message=too many commands (max 128)` |

The null-handle cases pass genuinely invalid handles to `guarded_pixel()` and
`guarded_hud()`, which check the handle before any pixel read or Nuklear call,
so the refusal is exercised rather than hard-coded.  `--bullets=0` and
non-numeric pool values are refused by the same range guard.  An oversized
stdin line is refused as `reason=stdin-oversized code=101`.
