# Data/config utilities — verification notes

## Scope and honesty statement

Five single-file C+ utilities that parse real-world-shaped data/config inputs
(CSV, INI, JSON, URLs, log lines) with **checked stdlib APIs** and explicit,
stable refusals. They are deterministic teaching examples, not production
parsers: they use fixed field layouts and hard caps, and they deliberately
refuse features outside those layouts. No clock, network, interactive prompt,
shelling out or user-specific path is involved. All fixtures are generated
from fixed bytes by `run.sh`.

Each utility is built with the repository C+ driver in strict, no-sanitizer
mode. Refusals come from explicit checks in the C+ code and the checked
stdlib (`--sanitize=none` is set; nothing depends on a sanitizer report).
Every line quoted below was observed by actually running the commands on
this host; no pass was assumed or fabricated.

## Files

| File | Purpose |
| --- | --- |
| `csvstat.cp` | CSV count/sum/min/max with overflow-safe accumulation; malformed rows, non-numeric cells, long lines and overflow refused |
| `iniparse.cp` | Fixed INI sections/keys/values; malformed lines, oversized names, duplicate keys, missing sections refused |
| `jsonfmt.cp` | Budgeted JSON parse + deterministic canonical pretty-print; malformed, truncated, deep and oversized input refused |
| `uriparse.cp` | scheme/host/port/path parser; bad ports, query/fragment/userinfo, bad schemes and oversized URLs refused |
| `logparse.cp` | Fixed-format log lines with level filter; malformed lines, bad timestamps/levels and long lines refused |
| `run.sh` | Builds all five, runs fixed scenarios under `timeout 30`, checks exit code + empty stderr + exact stdout, prints the summary line |

Hostile refusals (each exit 1, exact stdout):


`2147483647 + 1`-style overflow is avoided: `cs_add_checked()` guards the
addition *before* executing it (`LLONG_MAX - acc` / `LLONG_MIN - acc`), so no
signed-overflow UB occurs and no sanitizer is needed.

### jsonfmt.cp

```sh
timeout 30 "$D/jsonfmt" '{"name":"alice","age":30,"active":true,"tags":["a","b"]}'
```
```
JSON root object
JSON {
JSON   "name": "alice",
JSON   "age": 30,
JSON   "active": true,
JSON   "tags": [
JSON     "a",
JSON     "b"
JSON   ]
JSON }
```
```sh
timeout 30 "$D/jsonfmt" '[1,2,3]'
```
```
JSON root array
JSON [
JSON   1,
JSON   2,
JSON   3
JSON ]
```
Parsing uses `stdlib/json.hp::json_parse_budget(text, len, 8, &err)` with a
local 2048-byte input cap; the canonical byte stream comes from
`json_view::write()` (yyjson `NOFLAG`) and the formatter only re-lays it out
with deterministic indentation. Hostile refusals (each exit 1):

```sh
timeout 30 "$D/jsonfmt" '{"a":}'       # -> JSON error parse
timeout 30 "$D/jsonfmt" '{"a": 1'      # -> JSON error parse
timeout 30 "$D/jsonfmt" '[[[[[[[[[1]]]]]]]]]'  # -> JSON error depth
LONG2100=$(printf '%02100d' 0 | tr '0' 'x')
timeout 30 "$D/jsonfmt" "{\"k\":\"$LONG2100\"}"  # -> JSON error too-long
```
The depth case is distinguished by `err.code() == CPLUS_EXIT_BOUNDS` (101)
returned from the budget check, giving the stable `depth` token.


```
LOG match 2 2024-01-01T00:00:02Z INFO ready
LOG match 3 2024-01-01T00:00:03Z ERROR failed

```
Hostile refusals (each exit 1):

```sh
printf '2024-01-01T00:00:00Z BOGUS msg\n' > "$D/badlvl.log"
timeout 30 "$D/logparse" "$D/badlvl.log" all          # -> LOG error bad-level
printf '2024/01/01T00:00:00Z INFO msg\n' > "$D/badts.log"
timeout 30 "$D/logparse" "$D/badts.log" all           # -> LOG error bad-timestamp
printf '2024-01-01T00:00:00Z INFO\n' > "$D/nomsg.log"
timeout 30 "$D/logparse" "$D/nomsg.log" all           # -> LOG error malformed
LONG300=$(printf '%0300d' 0 | tr '0' 'x')
printf '2024-01-01T00:00:00Z INFO %s\n' "$LONG300" > "$D/long.log"
timeout 30 "$D/logparse" "$D/long.log" all            # -> LOG error line-too-long
```
The timestamp validator checks the fixed `YYYY-MM-DDTHH:MM:SSZ` *layout*
(digit positions and separators), not calendar ranges; the hostile fixture
violates the layout (`/` instead of `-`), which is refused.

## Refusal codes used

| Code | Name | Meaning here |
| --- | --- | --- |
| 101 | `CPLUS_EXIT_BOUNDS` | line/name/key/value too long, table overflow, sum overflow, JSON depth, oversized JSON/URL |
| 108 | `CPLUS_EXIT_UNSUPPORTED` | malformed rows/lines, non-numeric cells, bad scheme/host/port/level/timestamp, duplicate or missing keys, unknown command |
| 109 | `CPLUS_EXIT_IO` | cannot open fixture, read/close error |

## Checked-API / strict-mode findings

* `argv` is an FFI pointer: direct `argv[i]` is rejected by `--strict`
  (`CPLUS-FFI: unverifiable extent`). Every utility copies the slot with
  `__builtin_memcpy(&value, p + idx, sizeof(value))`, then copies the string
  into a local buffer via the checked `stdlib/string.hp::substr` (after a
  `size()` length check), and only then indexes it.
* `--strict` does not propagate initialisation through out-pointers, so
  parsed-out locals are initialised before the call (`long long cell = 0;`,
  `int port = -1;`) — matching the repository's existing convention.
* Reads use `file::read_line` with an `error *`. A line longer than the buffer
  yields `STDLIB_FAIL` with `CPLUS_EXIT_BOUNDS`, which is mapped to a stable
  `line-too-long` token rather than being silently truncated.
* `jsonfmt` uses `json_parse_budget` (depth cap) plus a local length cap,
  distinguishing `depth` (bounds error) from `parse` (yyjson error). Strings
  are freed with `json_view::write` + `json_free`, and the document with
  `json::drop()`.
* Numeric parsing uses `strtoll`/`strtol` with an explicitly initialised
  `end` pointer plus a manual sign/digit pre-check (so leading whitespace is
  refused) and `errno == ERANGE` handling, avoiding the strict checker's
  variable-division rule (no `/` on computed values anywhere in these files).
* No sanitizer was enabled and no live game/network/filesystem-write workflow
  was used; nothing here claims live-game success.
