# Deterministic Snake core example

## What this is (and is not)

**This is a deterministic core model of the Snake game logic. It is NOT the
interactive terminal game.** There is no `termios`, no `_kbhit`/`_getch`, no
`system("cls")`, no `sleep`, no wall clock and no `time(NULL)`-seeded
randomness anywhere in this directory. Given the same seed and the same
direction sequence, every run produces byte-for-byte identical output.

The interactive terminal game this models is
[`apps/legacy_examples/games/snake.c`](../../../games/snake.c) (repo path:
`apps/legacy_examples/games/snake.c`). That file is an interactive ncurses-free C program
with raw terminal input; do not confuse it with the deterministic core here.

## Files

| file | role |
| --- | --- |
| `snake_core.cp` | The core: fixed 20x20 board, `SnakeCore` state struct, `snake_core_init`, `snake_core_place_food`, `snake_core_set_food`, `snake_core_step`, collision detection (wall/self), score, game-over, render-to-buffer. Uses `stdlib/vector` for the body and `stdlib/error` for refusals (invalid direction, 180-degree reversal, wall/self collision, out-of-range food, full board, step-after-game-over). No I/O. Also contains a standalone self-test `main`. |
| `snake_cli.cp` | CLI driver. Includes `snake_core.cp` (embedded via `SNAKE_CORE_EMBEDDED`), reads a bounded direction sequence from argv or stdin, prints an `INIT` line, a board-state transcript after every step, and a final `SCENARIO ... ok 0|1` line. Exits 0 only when the expected scenario outcome matches. |
| `run.sh` | Builds both with the exact `c+ build` command below, runs the core self-test and 3 fixed scenarios under `timeout 30`, then prints `SNAKE_EXAMPLES <scenarios> <passed> <failed>`. |
| `.build/` | Generated binaries and self-test output (regenerated by `run.sh`). |

Direction encoding: `U/u/W/w` = up, `D/d/S/s` = down, `L/l/A/a` = left,
`R/r` = right. Seed is fixed at `12345`; food uses a fixed-seed LCG
(`1664525x + 1013904223`) and the first free cell at/after the PRNG offset.

Board glyphs: `.` empty, `O` head, `o` body, `F` food.

## Exact commands (cwd = repository root)

These are the commands `run.sh` issues:

```sh
./build/c+ build apps/legacy_examples/expanded/games/snake/snake_core.cp --strict --sanitize=none -I. -o apps/legacy_examples/expanded/games/snake/.build/snake_core
./build/c+ build apps/legacy_examples/expanded/games/snake/snake_cli.cp --strict --sanitize=none -I. -o apps/legacy_examples/expanded/games/snake/.build/snake_cli
timeout 30 apps/legacy_examples/expanded/games/snake/.build/snake_core
timeout 30 apps/legacy_examples/expanded/games/snake/.build/snake_cli growth R
timeout 30 apps/legacy_examples/expanded/games/snake/.build/snake_cli wall RRRRRRRRRR
timeout 30 apps/legacy_examples/expanded/games/snake/.build/snake_cli self RULD
```

One-shot verification:

```sh
apps/legacy_examples/expanded/games/snake/run.sh
```

Both builds are clean under `--strict --sanitize=none` (no warnings, no errors).
`argv` is read through a `__builtin_memcpy` slot accessor because the strict
checker cannot prove the extent of a direct `argv[i]` subscript.

## stdin fallback

With no direction arguments, directions are read from stdin (bounded to 256):

```sh
printf 'R' | timeout 30 apps/legacy_examples/expanded/games/snake/.build/snake_cli growth
# ... final lines:
# FINAL score 1
# SCENARIO growth score 1 over 0 reason none ok 1
```

## Notes on the core's refusals (`stdlib/error`)

`snake_core_step` returns `-1` and records an `error` (with a stable category
and message) when it refuses an invalid direction, a 180-degree reversal, a
step after game-over, a wall collision or a self collision. `place_food`
records a range error when the board is full, and `set_food` refuses an
out-of-range or body-occupied cell. These refusals are part of the
deterministic model; none of them print anything from the core itself.
