# Safety audit — `stdlib/net.hp`

Audit scope: header `stdlib/net.hp` (184 lines) and the two independent deep
suites that exercise it:

| Evidence | Exact path | Result |
|---|---|---|
| Original deep suite — **14 scenarios** | `tests/stdlib/deep_net.cp` / `.expected` | `SUMMARY 8 6 0 0` (8 SUCCESS, 6 RECOVERABLE, 0 FATAL, 0 SKIP) |
| Task-5 gap suite — **9 checks** | `tests/stdlib/deep_net_task5.cp` / `.expected` | `NET_TASK5 9 0` |
| Original contract | `docs/stdlib/DEEP_NET_CONTRACT.md` | "verified, no defects found" (lines 3-6); 18 endpoints table |
| Task-5 contract | `docs/stdlib/DEEP_NET_TASK5_CONTRACT.md` | "no defect found" (line 9) |
| Historical header fixes | git `558bc36`, `df3bc7b` (`git show <sha> -- stdlib/net.hp`) | fd 0/1/2 guard, short-write loop, EINTR retries, port range, error categories |

Both suites were built in default Safe/UBSan, `--strict --sanitize=none` and
explicit `--sanitize=undefined` modes (rc 0), run under `timeout 60`/`timeout
30`, with byte-identical stdout, empty stderr and no fd leak
(`DEEP_NET_CONTRACT.md:136-153`, `DEEP_NET_TASK5_CONTRACT.md:118-145`). The
original suite's stdout was identical across 10 repeated runs.

**Isolation evidence (required):** both suites use **only** `AF_INET` sockets
bound to `INADDR_LOOPBACK` (`127.0.0.1`) and `AF_UNIX` `socketpair()`s; every
remote peer is a `fork()`ed child of the test process, exchanging status over
anonymous `pipe()`s. **No external server, no well-known service, no off-host
connection, no `data/` asset and no user path is used**
(`DEEP_NET_CONTRACT.md:17-18`, `DEEP_NET_TASK5_CONTRACT.md:25-29`).

**Evidence standard:** the suites assert return values, error categories and
messages, descriptor counts and byte-exact payloads. They are not proof of
memory safety or absence of UB; ASan is unavailable on this host
(`docs/LIMITATIONS.md:139-141`). Clean UBSan builds cover only instrumented
paths. No memory-safety claim is made from passing tests.

## 1. Public API surface

C+ classes have no explicit `public:`/`private:` sections here; all methods are
callable from the suites.

| Symbol (path with line) | Signature | Result protocol |
|---|---|---|
| `listener` constructor (`stdlib/net.hp:106`) | `listener(int port)` | Binds loopback port; valid only for `0..65535` and successful `socket`/`bind`/`listen`; otherwise inert (`fd = -1`) |
| `listener::is_valid` (`stdlib/net.hp:132`) | `int is_valid(void)` | `fd >= 3 || (owns && fd >= 0)` — zero-init/borrowed fd 0/1/2 are inert |
| `listener::descriptor` (`stdlib/net.hp:136`) | `int descriptor(void)` | raw fd or `-1` |
| `listener::bound_port` (`stdlib/net.hp:140`) | `int bound_port(void)` | `ntohs(getsockname(...))`; `0` if invalid or query fails |
| `listener::accept` (`stdlib/net.hp:150`) | `connection accept(void)` | retries `EINTR`; returns `connection(-1)` if invalid |
| `listener::drop` (`stdlib/net.hp:161`) | `void drop(void)` | closes only if `owns && fd >= 0`; sets `fd = -1`, `owns = 0`; idempotent |
| `listener_borrow` (`stdlib/net.hp:170`) | `static inline listener listener_borrow(int fd)` | wraps fd with `owns = 0`; never closes |
| `connection(int)` internal ctor (`stdlib/net.hp:24`) | `connection(int descriptor)` | `owns = descriptor >= 0` |
| `connection::is_valid` (`stdlib/net.hp:31`) | `int is_valid(void)` | same fd 0/1/2 rule as listener |
| `connection::descriptor` (`stdlib/net.hp:35`) | `int descriptor(void)` | raw fd or `-1` |
| `connection::read` (`stdlib/net.hp:41`) | `int read(char *buf, size_t capacity, error *err)` | byte count; `STDLIB_EOF`(1); `STDLIB_FAIL`(-1). Rejects invalid handle/NULL buf/zero capacity with `CATEGORY_INVALID`; clamps capacity to `INT_MAX`; retries `EINTR`; hard error → `CATEGORY_IO` / `"connection::read failed"` |
| `connection::write` (`stdlib/net.hp:64`) | `int write(const char *data, size_t length, error *err)` | loops until all bytes sent; retries `EINTR`; `write()==0` → `STDLIB_FAIL` / `CATEGORY_IO` / `"connection::write made no progress"`; hard error → `"connection::write failed"`; NULL data/invalid handle → `CATEGORY_INVALID`; zero-length write on valid handle → `STDLIB_OK` |
| `connection::drop` (`stdlib/net.hp:93`) | `void drop(void)` | same ownership rule as `listener::drop`; idempotent |
| `connection_borrow` (`stdlib/net.hp:177`) | `static inline connection connection_borrow(int fd)` | wraps fd with `owns = 0`; never closes |

RAII scope-exit dropping is generated by the compiler for owned locals
(`compiler/Sema/RaiiLowering.cpp`, cited in `DEEP_NET_CONTRACT.md:125-131`).

`SO_RCVTIMEO`/`SO_SNDTIMEO`, a 5 s `alarm()` per forked child, a bounded
3 s reap loop, plus a process watchdog (`45 s` in `deep_net.cp:175`,
`25 s` in `deep_net_task5.cp:142`) that writes to stderr and `_exit(90)`.
`SIGPIPE` is ignored/routed to a no-op handler so a reset peer returns an error
rather than terminating the process (`DEEP_NET_CONTRACT.md:22-24`,
`DEEP_NET_TASK5_CONTRACT.md:35-37`). Caller-managed `SIGPIPE` is documented as
caller responsibility, not a `net.hp` guarantee.

## 4. Interruption / timeout behavior

- `connection::read` retries `EINTR` in a `do/while` loop
  (`stdlib/net.hp:51-53`); VERIFIED by both injected EINTR
  (`deep_net.cp:510-532`) and a real non-SA_RESTART `SIGALRM` in a forked child
  (`deep_net_task5.cp:349-374`, `net_read_eintr_signal`).
- `listener::accept` retries `EINTR` (`stdlib/net.hp:153-155`); VERIFIED by a
  real `SIGALRM` armed **before** the blocking call
  (`deep_net_task5.cp:437-447`, `net_accept_eintr_signal`).
- `connection::write` retries `EINTR` per chunk and continues after short
  writes (`stdlib/net.hp:74-89`); VERIFIED by `partial_write_short` and
  `fault_write_no_progress`.
- Bounds: 3 s poll handshakes, 3 s socket timeouts, 5 s child alarms, 3 s
  bounded reap with `SIGKILL`, 25 s (task5) / 45 s (original) process watchdog.
  `SIGPIPE` ignored so reset peers yield returned errors
  (`DEEP_NET_CONTRACT.md:19-24`, `DEEP_NET_TASK5_CONTRACT.md:31-37`).
- **UNTESTED:** repeated signals during a single blocking call (one signal per
  scenario); timeouts actually expiring (they are configured but never fire);
  a blocked `read`/`accept` receiving a signal whose handler uses `SA_RESTART`;
  watchdog/timeout expiry behaviour itself.

## 6. Confirmed defects fixed (reproducer / regression)

### 6.1 Header defects (historical, fixed)

`stdlib/net.hp` was **not modified by the deep-suite work**; both contracts
report no defect found (`DEEP_NET_CONTRACT.md:3-6, 114-117`,
`DEEP_NET_TASK5_CONTRACT.md:9`). Git history nevertheless shows concrete
safety defects that were fixed earlier, each now covered by a deep regression:

| # | Defect in earlier `net.hp` | Reproducer / regression now in suite |
|---|---|---|
| 1 | `is_valid()` was `fd >= 0`, so zero-initialised handles (fd 0, `owns = 0`) and borrowed stdio fds appeared usable; `read`/`write`/`accept`/`bound_port` could target process stdin/stdout/stderr. Fixed to `fd >= 3 || (owns && fd >= 0)` (`git show 558bc36`). | `deep_net.cp:289-318` `borrow_no_close_012` (fcntl before/after), `456-485` `invalid_handles` (`ih_bad`, `ih_zl`, `ih_zc`, `ih_bl`); `DEEP_NET_CONTRACT.md:50, 55` |
| 2 | `connection::write` made a single `write()` call and treated any short write as failure — a 65536-byte loopback payload could fail. Fixed with the `sent < length` loop (`git show 558bc36`). | `deep_net.cp:394-454` `partial_write_short` (injected 1024-byte cap; child verifies all bytes) |
| 3 | No `EINTR` retry in `read` or `accept`; a signal could abort a transfer. Fixed (`git show 558bc36` for write, `df3bc7b` for read/accept). | `deep_net.cp:510-532` `fault_read_retry` (injected EINTR); `deep_net_task5.cp:312-415` `net_read_eintr_signal` and `417-503` `net_accept_eintr_signal` (real `SIGALRM`) |
| 4 | `write() == 0` was not distinguished from success/progress — an infinite loop or false success was possible. Fixed with `"connection::write made no progress"` failure (`git show 558bc36`). | `deep_net.cp:487-508` `fault_write_no_progress` (injected `write()==0`, then recovery, zero-length write) |
| 5 | `listener(int port)` accepted any `port >= 0`, so values > 65535 were truncated by `htons`. Fixed with `port <= 65535` (`git show df3bc7b`). | `deep_net.cp:213-228` `port_invalid_range` (-1, 70000, `INT_MIN`); `DEEP_NET_CONTRACT.md:48, 132-134` |
| 6 | `bound_port()`/`accept()` checked `fd < 0` instead of `is_valid()`, so a borrowed fd 0 could be queried/accepted from; invalid-argument errors were categorised as IO. Fixed to `is_valid()` + `error_fail_cat(... INVALID ...)` (`git show 558bc36, df3bc7b`). | `deep_net.cp:456-485` `invalid_handles` (exact `CATEGORY_INVALID` and messages); `deep_net.cp:180-194` uses `bound_port()` on a valid handle |
| 7 | `connection::read` passed an unchecked `size_t capacity` to `read()` (implementation-defined for values > `SSIZE_MAX`/`INT_MAX`). Fixed with clamp to `INT_MAX` (`git show df3bc7b`). | Clamp is present at `stdlib/net.hp:49-50`; **not directly exercised** — see §7 |

### 6.2 Test-side defects found while establishing the contract (fixed)

| Defect | Reproducer | Fix / regression |
|---|---|---|

| The EINTR `alarm(1)` was armed *after* `accept()` returned, so no signal interrupted it and the scenario self-reported SKIP. | `DEEP_NET_TASK5_CONTRACT.md:83-86` | `deep_net_task5.cp:441` arms the alarm before the blocking call; `net_accept_eintr_signal` now passes deterministically |

### 6.3 Documented non-defects

1. **Caller-managed `SIGPIPE`**: `net.hp` does not suppress it; the suites ignore
   it and verify the returned `STDLIB_FAIL`/IO error
   (`DEEP_NET_CONTRACT.md:118-120`).
2. **`SO_REUSEADDR` ordering**: a failed-bind test is deterministic only when
   the occupying socket did not set `SO_REUSEADDR`; the test uses a non-reuse
   blocker in a forked child (`DEEP_NET_CONTRACT.md:121-124`).
3. **No address-string API**: see §8.
4. **No active-connect API**: the `ECONNREFUSED` case uses a raw non-blocking
   socket; the complementary `net.hp`-observable case is the RST write failure
   (`DEEP_NET_TASK5_CONTRACT.md:62-67`).
5. **C+ RAII name tracking** is a test-authoring constraint, not a header
   defect (`DEEP_NET_CONTRACT.md:125-131`, `DEEP_NET_TASK5_CONTRACT.md:87-89`).

**Defect counts (net):** header defects fixed in audited version **0**;
historical header defects fixed with deep-suite regression coverage **7**;
test-side defects fixed **4**; open defects **0**; documented non-defects **5**.

## 7. Remaining untested paths (UNTESTED — not claimed verified)

1. `connection::read` capacity clamp to `INT_MAX` (`stdlib/net.hp:49-50`) —
   no test passes a capacity > `INT_MAX`; a real > 2 GiB buffer is required.
2. `connection::write` with `length > INT_MAX` — no clamp exists; the partial
   loop is only exercised with a 65536-byte payload.
3. Port boundary `65536` exactly (suite uses `70000` and `INT_MIN` for
   out-of-range); `65535` is the only upper bound exercised.
4. Non-loopback bind (`INADDR_ANY`, a specific external interface), IPv6
   (`AF_INET6`) and hostname resolution — no API parameter exists; hardcoded
   `AF_INET`/`INADDR_LOOPBACK` at `stdlib/net.hp:112-118`.
5. Privileged port bind (< 1024) as non-root (`EACCES`) — untested.
6. `setsockopt(SO_REUSEADDR)` return value is unchecked
   (`stdlib/net.hp:114`); its failure path is untested.
7. `listen` backlog overflow / connection queue saturation (backlog fixed at
   `1`) — untested.
8. `listener::accept` with a non-blocking listener (`EAGAIN`/`EWOULDBLOCK`
   would spin) — untested; suite listeners are blocking.
9. `getsockname` failure inside `bound_port()` (`stdlib/net.hp:145`) — not
   injectable; untested.
10. Timeouts actually expiring (`SO_RCVTIMEO`/`SO_SNDTIMEO`, poll handshakes,
    watchdogs) — configured but never fire in recorded runs.
11. Multiple consecutive signals during one blocking `read`/`accept`, and
    handlers installed with `SA_RESTART` — untested.
12. Half-close (`shutdown(SHUT_WR)`), urgent data, and zero-length writes
    beyond the one valid-handle case (`deep_net.cp:503`) — untested.
13. Concurrent use of one `listener` from multiple threads/processes;
    `SO_REUSEPORT`; fd exhaustion during `accept` — untested.
14. Validating that a lazily reused owning-local name is diagnosed by the
    compiler — the constraint is documented (`DEEP_NET_CONTRACT.md:125-131`)
    but not a compile-time negative test.
15. Behaviour when fd 0/1/2 are closed before constructing a listener (so
    `accept` could legitimately return fd 0) — untested edge of the
    `owns && fd >= 0` clause.

## 8. SKIPs

- **`net_invalid_address` — SKIP (the only SKIP in the net suites).** Reason,
  emitted verbatim at `deep_net_task5.cp:270-275` and recorded in
  `tests/stdlib/deep_net_task5.expected`:

  > `stdlib/net.hp listener(port) takes only an integer port and always binds
  > INADDR_LOOPBACK; connection has no address argument either. Strings such
  > as "not.an.address" or "" cannot be passed to any net.hp API, so no
  > INVALID_ADDRESS case exists.`

  Elaborated in `DEEP_NET_TASK5_CONTRACT.md:69-74`: the API has no
  address-string parameter, so an invalid-address test cannot be constructed
  without fabricating a case. The check is counted as a pass (`t5_skip`
  increments `t5_checks`, `NET_TASK5 9 0`) and a `SKIP_REASON` line is printed.

- **Portability SKIP rules built into `deep_net.cp` but not triggered**
  (`DEEP_NET_CONTRACT.md:99-112`): `port_65535` if `127.0.0.1:65535` is
  already bound; `bind_in_use_fork` if `pipe()` fails or the child cannot
  publish its port in 3 s; `fault_socket_emfile` if `pipe()` fails;
  `no_fd_leak` if `/dev/fd` cannot be opened.
- Additional conditional SKIPs in `deep_net_task5.cp` (not triggered):
  `pipe()/socketpair()` unavailable for `net_read_eintr_signal`,
  `net_accept_eintr_signal`, `net_partial_read`; SIGALRM not delivered while
  blocked; `/dev/fd` unavailable. The original suite recorded `SUMMARY 8 6 0
  0` and the task-5 suite recorded `NET_TASK5 9 0`, i.e. zero triggered SKIPs
  in `deep_net.cp` and exactly the documented `net_invalid_address` SKIP in
  `deep_net_task5.cp`.
