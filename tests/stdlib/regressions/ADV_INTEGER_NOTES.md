## Design and bounds (no memory exhaustion)

`adv_integer_bounds.cp` pins `STDLIB_ALLOC_LIMIT` to **4096 bytes in source**,
before the includes, because the C+ strict bounds checker does not consume `-D`
flags (only the C backend does). No `-D` is needed on the command line. With
that limit:

- the largest single allocation is 4096 bytes;
- capacity doubling is reached after exactly 1024 `int`s (4 KiB) in `vector`,
  `deque`, `stack` and `queue`; the 1025th push must be refused;
- `string` tops out at 4095 content bytes + NUL, so the 4096-byte generated
  token is refused by `append` without allocating;
- `stdlib_calloc` count*size overflow is exercised with `SIZE_MAX`,
  `UINT64_MAX`, `INT_MAX*INT_MAX` etc., all refused before any allocation;
- telemetry (`alloc_count`, `api_failures`, `ownership_violations`) proves that
  refusals allocate nothing and do not corrupt allocator metadata.

`adv_long_input.cp` generates all bytes into `static char ali_src[4128]` and
installs them as `stdin` with `fmemopen()` (restoring `stdin` after each case).
Tokens and lines are bounded at **4096 bytes**; the file-based line case writes
4122 generated bytes to a `tmpfile()` and rewinds it. There is no fault
injection, no unbounded growth, and no external file or user path.

## Defect status

**No reachable defect was reproduced.** All 66 checks pass in all three modes,
including strict mode and UBSan. No header was edited.

One *unreachable* internal-helper observation was probed out-of-band (scratch
file in the temp directory, not part of either test): `stdlib_map_rebuild_capacity`
in `stdlib/collections.hp` documents "0 on overflow", but with the artificial
arguments `(SIZE_MAX, SIZE_MAX)` it returns `SIZE_MAX` because
`((unsigned long long)count + 1ULL) * 2ULL` wraps to 0 in unsigned arithmetic:

```
rebuild_maxminus1 0
rebuild_max 18446744073709551615
next_pow2_max 0
```

This is **not asserted as a pass or a failure in the owned tests**, and it is
not a reachable defect through the public container API: callers pass
`count <= capacity` where `capacity` is a power of two never larger than
`SIZE_MAX >> 2` (`stdlib_map_next_pow2` returns 0 above that), and the rebuild
itself rejects any cap larger than `STDLIB_ALLOC_LIMIT / sizeof(slot)`. The
test therefore pins only the reachable guard
`stdlib_map_rebuild_capacity(SIZE_MAX - 1, SIZE_MAX - 1) == 0` and the real
doubling refusals at the pinned 4096-byte limit. Minimal repro, if a future
hardening pass wants to close the helper-level wrap, is a direct call with
both arguments `SIZE_MAX` (as above); no header change is included here.
